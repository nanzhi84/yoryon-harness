# 项目文档导航与维护规范

本项目文档体系按内容的生命周期、变动频率与职责边界进行划分。除项目根目录下的 [README.md](../README.md)（项目门面介绍）外，`docs/` 目录严格仅保留以下四大子目录（需求设计稿与改动过程记录优先托管于 GitHub Issues / PR，也可视情况临时放于本地忽略目录 `work/` 中维护；版本发布说明统一托管于 GitHub Releases，严禁在仓库内维护 `docs/spec/` 或 `CHANGELOG.md`）：

## 1. architecture/（全局架构现状）
承载系统当前已落地的全局架构状态，属于随代码同步更新的**活文档**。遵循**单一事实源（Single Home of Facts）**与**“只写指针与边界，不复述源码细节”**原则：每项架构事实在整个仓库中只在此处定义一次，核心断言与结构定义必须直接链接到真实源码路径。

为兼顾完备性与防膨胀，本目录按正交架构维度**强制拆分为 4 个必填文件 + 1 个按需文件**（严禁把不同维度混塞进 `overview.md`，也严禁新建子目录或任意 `<topic>.md` 专题文件），图表统一使用 **Mermaid** 绘制：
- **`overview.md`（必填 · 上下文与模块边界）**：用 Mermaid `flowchart` 画出系统外部边界、核心模块划分与单向依赖方向，并列出各模块对应的真实源码目录或入口链接（不列全量文件树，不逐个解释工具函数）。
- **`data-flow.md`（必填 · 核心执行链路与数据流）**：用 Mermaid `sequenceDiagram`（或 `flowchart`）画出 1~3 条最核心的端到端主干路径，说明输入进入、阶段转换、副作用发生与落盘/输出位置（不画边缘分支或单个接口细节）。
- **`data-model.md`（必填 · 核心领域模型与状态机）**：用 Mermaid `erDiagram` / `stateDiagram-v2` 描述核心实体关系与关键对象生命周期状态流转，并直接链接到源码中的权威 Schema/类型定义位置（不将结构体字段逐一抄成表格）。
- **`invariants.md`（必填 · 不变量与横切约束）**：用简短清单或表格记录并发/锁模型、事务与幂等边界、错误处理/重试策略、安全/权限边界、性能红线与明确 Non-goals（不写历史演进故事，决策原因放 `adr/`）。
- **`deployment.md`（按需 · 部署与运行拓扑）**：仅当项目存在多进程、容器、队列、云资源或网络隔离时编写（Mermaid `flowchart` 描述进程/存储/网络与环境变量边界；纯本地 CLI 或库直接省略；具体运维命令放 `runbooks/`）。

## 2. adr/（架构决策记录）
专门记录不可逆或高成本架构设计与关键技术选型的演进链路及权衡过程（记录源码无法体现的“为什么选 A 而非 B”）。文档采用四位数递增编号命名（格式为 `0001-decision-title.md`），遵循不直接覆盖原决策的原则。当既有决策在后续实践中被推翻时，按以下三步处理（可通过 `harness adr supersede <old-id> <new-slug>` 自动完成）：
1. 新建一篇更高编号的 ADR 文档，阐述新的技术方案、上下文及替代关系（注明取代了哪篇旧 ADR）。
2. 在旧 ADR 文档的顶部元数据中，将状态更新为已被取代（例如标记为 `Superseded by [ADR-0012](../0012-xxx.md)`），并在文档底部追加一段失效说明，如实记录原方案在实际落地中遇到的问题或不再适用的原因，以此沉淀踩坑经验。
3. 将更新完状态的旧文档移入 `adr/superseded/` 子目录中归档，保持 `adr/` 外层主目录永远只展示当前依然生效的架构原则。

## 3. runbooks/（高频标准运维与开发 SOP）
仅存放会被反复执行和校验的标准操作规程（SOP），例如开发环境搭建、端到端测试验收、发版/部署流程与数据库迁移操作。严禁将一次性排障日记或临时实验过程堆入本目录，确保每篇手册都能在日常开发与发版中被持续验证、不腐化。

## 4. reference/（外部参考与调研沉淀）
用于存放第三方接口规范、行业标准等原始外部资料，以及经过提炼总结后的技术调研文档。
- **定稿落库即封存**：无论是外部文件还是调研总结文档，一旦合入仓库即视为静态基线，后续不再直接修改（若有新结论应作为新文件补充）。
- **三列索引登记（[INDEX.md](reference/INDEX.md)）**：目录根部维护 `INDEX.md` 索引文件，仅保留 **文件路径**、**来源链接 / 背景说明**、**备注** 三列。每次新增参考资料时必须同步登记。
